Four-mission proof sprint

Do the work. Keep the evidence.

Check a mission only after the proof exists. Progress stays in this browser and also appears in the Modern Skills catalog.

  1. 01

    Design the API boundary

    Define resources, validation, errors, idempotency, pagination, and versioning around one user outcome.

    Proof: An API contract with example success and failure exchanges.
  2. 02

    Choose the consistency model

    Map the data lifecycle and decide where strong consistency, eventual consistency, transactions, or compensation apply.

    Proof: A state-flow diagram with one rejected alternative.
  3. 03

    Engineer for partial failure

    Add timeouts, bounded retries, idempotency, overload behavior, and a recovery path for one dependency failure.

    Proof: A failure test that demonstrates safe degradation.
  4. 04

    Trace the user request

    Connect structured logs, metrics, and traces from an external request through storage or a queue.

    Proof: A trace-led incident explanation and scaling threshold.
