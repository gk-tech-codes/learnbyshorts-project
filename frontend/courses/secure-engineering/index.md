## Intended outcome

A security-reviewed application with a threat model, hardened authentication, and tested abuse cases.

## Why this path is current

Fast AI-assisted delivery expands both capability and attack surface; secure defaults must move equally fast.

## Proof missions

### 1. Threat-model the outcome

- Action: Map assets, actors, trust boundaries, abuse paths, and the impact of failure.
- Evidence to produce: A threat model with prioritized mitigations.

### 2. Harden identity and data

- Action: Verify authentication, authorization, session handling, storage exposure, and least privilege.
- Evidence to produce: A security checklist with anonymous-access tests.

### 3. Secure the delivery chain

- Action: Review dependencies, build permissions, secret handling, and release provenance.
- Evidence to produce: A dependency and pipeline risk report.

### 4. Test AI abuse boundaries

- Action: Probe prompt injection, data leakage, unsafe tool use, over-permission, and unsupported output.
- Evidence to produce: An adversarial test set and one repaired control.
