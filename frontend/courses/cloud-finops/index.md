## Intended outcome

A serverless service with an architecture diagram, budget guardrails, and operational runbook.

## Why this path is current

Modern builders must understand both reliability and unit economics before scaling infrastructure.

## Proof missions

### 1. Choose the cheapest adequate shape

- Action: Compare static, serverless, container, and managed options against traffic and reliability needs.
- Evidence to produce: An architecture decision record with estimated cost drivers.

### 2. Make infrastructure repeatable

- Action: Describe resources, permissions, encryption, and deletion safety as code.
- Evidence to produce: A reviewed change set with no public datastore.

### 3. Observe the user outcome

- Action: Define logs, metrics, alarms, and a trace from failure symptom to likely cause.
- Evidence to produce: A dashboard or runbook with alert thresholds.

### 4. Install cost guardrails

- Action: Set a budget, identify variable-cost events, and create a frugal degradation plan.
- Evidence to produce: A monthly cost envelope and shutdown checklist.
